Launch plan: cron job heartbeat monitor

Your scheduled job pings a URL when it finishes. If the ping doesn't arrive on time, you get an alert. Open source, free tier that stays free, paid plans for teams. Ten weeks from first commit to public launch, then about 3 hours a week.

1. Positioning: why someone picks yours

This market is crowded. Healthchecks.io leads, Cronitor and Dead Man's Snitch are established, and many small clones launched in 2025–26. A generic "cron monitor" will not stand out. Lead with four things the others don't combine.

"The EU-hosted heartbeat monitor for teams on Kubernetes and GitHub Actions, that opens a ServiceNow incident when a job goes quiet."

  • EU-hosted, EU companyData stays in the EU. GDPR data processing agreement on every paid plan. Prices in EUR.
  • Kubernetes + GitHub Actions nativeA Helm chart that finds CronJobs on its own, and a GitHub Action for scheduled workflows. No code changes per job.
  • ServiceNow + Teams alertsEnterprises run on ServiceNow and Microsoft Teams. Few small monitors integrate with ServiceNow. You know the platform.
  • Monitors as codeDefine checks in a YAML file in the repo. CI creates and updates them. Nothing to click.

2. Timeline

  1. Week 0–1Validate

    Check the angle before building

    • Pick a name. Check the .com/.eu domain, GitHub org, npm, Docker Hub, and the EU trademark register (EUIPO).
    • One-page landing site with the positioning line and a waitlist form.
    • Talk to 10–15 people: colleagues, ServiceNow contacts, DevOps friends. Ask how they find out a backup or nightly job didn't run today.

    Done when: 30+ waitlist sign-ups, or at least 5 people say "I'd pay for the ServiceNow or Kubernetes part".

  2. Week 2–6Build v1

    The smallest product that works every time

    • Ping endpoint: GET/POST /ping/<uuid>, plus /start and /fail to measure run time and record failures.
    • Schedules: fixed period + grace time, and cron expressions with time zones.
    • Alerts: email, Slack, Microsoft Teams, Discord, generic webhook. ServiceNow incident on paid plans.
    • Dashboard: list of checks, status, last ping, a 30-day log per check.
    • Teams + Stripe billing. Self-host with one docker compose up.

    Done when: it has monitored your own jobs for 7 days with no missed or false alerts.

  3. Week 7–8Private beta

    20–30 real users, free

    • Invite the waitlist. Watch where people get stuck in onboarding.
    • Write 6 copy-paste guides: crontab, systemd timers, Kubernetes CronJob, GitHub Actions, Windows Task Scheduler, Django/Celery beat.
    • Ship the Helm chart and the GitHub Action.

    Done when: 10 beta users have 3+ active checks each, and a new user gets to their first alert in under 5 minutes.

  4. Week 9–10Public launch

    Launch in waves, not all on one day

    • Day 1: open the GitHub repo + post in r/selfhosted (the self-host angle fits there best).
    • Day 3: publish a technical article and submit it to Hacker News (see channels below).
    • Day 5: Show HN, r/devops, r/kubernetes, dev.to.
    • Day 8: Product Hunt. Week 2: pitch kode24.no as a Norwegian open-source story.

    Done when: 300 sign-ups and your first 3 paying customers.

  5. Month 3–12Grow on autopilot

    Content and listings that keep working without you

    • One guide a month targeting a search: "monitor pg_dump backups", "restic backup alert", "certbot renew failed", "Laravel scheduler monitoring".
    • Honest comparison pages: vs Healthchecks.io, vs Cronitor, vs Dead Man's Snitch.
    • Listings: awesome-selfhosted, Artifact Hub (Helm), GitHub Marketplace (Action), Docker Hub, openalternative.co, AlternativeTo.
    • Later, only if asked for: a Terraform provider, and the ServiceNow Store.

    Done when: most new sign-ups come from search and listings, not from your posts.

3. Scope: what keeps upkeep at 3 hours a week

In v1

  • Heartbeat checks with schedules and grace time
  • Start/fail signals and run-time history
  • Email, Slack, Teams, Discord, webhook, ServiceNow
  • Teams, billing, API, YAML config
  • Docker image for self-hosting

Not now (each one adds ops work)

  • SMS and phone calls: per-message cost, fraud risk
  • Website uptime checks: a different, busier product
  • Public status pages: a product of its own
  • Log storage beyond short ping bodies
  • Mobile app: use push via Slack/Teams instead

9. Launch-day checklist

  • Your own jobs have been monitored for 7 days, no missed or false alerts
  • Sign-up to first alert in under 5 minutes, tested by someone new
  • README with a GIF, one-command self-host, and the AGPL license
  • Pricing page, terms, privacy policy, GDPR data processing agreement
  • Stripe live mode and VAT tested with a real card
  • Public status page for the monitor itself
  • Off-site backup restored once, as a test
  • Six setup guides live, plus the Helm chart and GitHub Action
  • HN article and r/selfhosted post drafted, with answers to likely questions
  • Support email works, and you've blocked time for replies on launch week

The ping, as users will see it

# crontab: back up the database nightly, ping only if it succeeds
0 2 * * *  pg_dump mydb | gzip > /backups/db.gz && curl -fsS -m 10 --retry 3 https://ping.example.eu/3f9c2a1e

One line per job. If the backup fails, curl never runs, and the alert fires once the grace time passes.
